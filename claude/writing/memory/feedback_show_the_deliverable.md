---
name: feedback_show_the_deliverable
description: When asked for a deliverable, print the deliverable. Never a table of what changed, never a list of files touched. The artifact is the answer.
metadata:
  type: feedback
---

Asked for a bug report, a comment, a patch or a testcase, print that thing, in full, paste-ready.

Do not answer with a was/now table of the edits, a list of files touched, a summary of which rules were applied, or a closing offer to print the real thing. If "want the full body printed?" would fit at the end, the answer should already have been the body.

The same holds for a redo. "Redo the prose" means show the redone prose, not a description of how it was redone.

A changelog belongs after the artifact, in one or two lines, and only when a change needs calling out.

**Why:** the artifact is what the reader signs off on. Anything else costs them an extra exchange.

**How to apply:** before sending, ask "have I printed the thing that was asked for?". If not, print it.
